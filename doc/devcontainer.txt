INTRODUCTION                                      *devcontainer-introduction*

devcontainer.nvim is a Neovim plugin that enables running language servers
inside a Dev Container while Neovim continues to run on the host machine.

The plugin wraps language server startup commands with `devcontainer exec`,
preserving stdin/stdout so LSP communication remains transparent to Neovim.

Key features:
- Transparent LSP command wrapping with `devcontainer exec`
- Interactive terminal support for running commands in the container
- Automatic loading of `.devcontainer/init.lua` or `.devcontainer/init.vim`
- Minimal configuration required
- No modification of LSP protocol messages

Requirements:
- Neovim >= 0.8
- Dev Container CLI installed (https://github.com/devcontainers/cli)

==============================================================================
INSTALLATION                                      *devcontainer-installation*

Using a plugin manager (e.g., lazy.nvim):

>
  {
    "keyhoh/devcontainer.nvim",
    config = function()
      require("devcontainer").setup()
    end,
  }
<

Using vim-plug:

>
  Plug 'keyhoh/devcontainer.nvim'
<

Then in your init.lua:

>
  require('devcontainer').setup()
<

CONFIGURATION                                    *devcontainer-configuration*

The plugin is configured via the setup() function:

>
  require('devcontainer').setup({
    auto_start = true,  -- Automatically start Dev Container (default: true)
    log_level = 'error' -- Log level: 'error', 'info', or 'debug' (default: 'error')
  })
<

log_level~
  - 'error': Only log errors
  - 'info': Log errors and info messages
  - 'debug': Log all messages including debug output

Dev Container Init Files~

The plugin automatically loads initialization files from the Dev Container
directory. This allows you to define Dev Container-specific Neovim configuration.

When setup() is called, the plugin searches for:
  1. `.devcontainer/init.lua` (Lua configuration)
  2. `.devcontainer/init.vim` (Vim configuration)

If found, the file is automatically loaded. If both exist, `.lua` takes precedence.

Example `.devcontainer/init.lua`:
>
  -- Dev Container-specific configuration
  vim.opt.undodir = '/tmp/.nvim-undo'
  
  -- Configure container-specific LSP servers
  require('devcontainer').setup({ log_level = 'debug' })
<

Example `.devcontainer/init.vim`:
>
  " Dev Container-specific configuration
  set undodir=/tmp/.nvim-undo
<

COMMANDS                                            *devcontainer-commands*

:DevcontainerUp                                       *:DevcontainerUp*
  Start the Dev Container for the current workspace (current directory).
  Displays a notification on success or failure.

  Example:
  >
    :DevcontainerUp
  <

:DevcontainerExec {cmd}                             *:DevcontainerExec*
  Execute a command inside the Dev Container in an interactive terminal.
  The command is wrapped with `devcontainer exec` and run in a terminal
  buffer, allowing full interactivity (stdin/stdout).

  This command supports any executable available in the Dev Container,
  including interactive tools like bash, psql, node REPL, etc.

  Examples:
  >
    :DevcontainerExec bash
    :DevcontainerExec psql -h localhost -U postgres
    :DevcontainerExec node
    :DevcontainerExec npm run dev
  <

LSP INTEGRATION                                        *devcontainer-lsp*

The plugin provides transparent LSP integration by automatically wrapping
language server commands to execute inside the Dev Container.

When a Dev Container configuration is detected (`.devcontainer/devcontainer.json`
or `.devcontainer.json`), LSP commands are automatically wrapped with
`devcontainer exec`, allowing language servers to run inside the container
while Neovim LSP client runs on the host.

LSP Configuration~

Use the wrap_lsp_cmd() function to wrap individual LSP commands:

>
  require('devcontainer').setup()

  vim.lsp.config('gopls', {
    cmd = require('devcontainer').wrap_lsp_cmd({ 'gopls' }),
  })

  vim.lsp.enable('gopls')
<

For more complex configurations, use wrap_for_lsp() to wrap an entire
LSP config table:

>
  local devcontainer = require('devcontainer')

  vim.lsp.config('tsserver', devcontainer.wrap_for_lsp({
    cmd = { 'typescript-language-server', '--stdio' },
    name = 'tsserver',
  }))

  vim.lsp.enable('tsserver')
<

How it works~

When wrap_lsp_cmd() is called:
  1. The plugin detects if a Dev Container exists in the workspace
  2. If found, the Dev Container is started (if not already running)
  3. The LSP command is wrapped with `devcontainer exec`
  4. The wrapped command is returned and used by Neovim LSP

Example transformation:
  Original:   ['gopls']
  Wrapped:    ['devcontainer', 'exec', '--workspace-folder', '/path/to/project', 'gopls']

stdin/stdout are preserved through the wrapper, ensuring transparent LSP
communication between Neovim and the language server.

API                                                    *devcontainer-api*

devcontainer.setup({opts})                       *devcontainer.setup()*
  Initialize the plugin with optional configuration.
  This function must be called before using the plugin.

  Parameters:
  - {opts} (table, optional): Configuration options
    - auto_start (bool): Automatically start Dev Container (default: true)
    - log_level (string): Logging level (default: 'error')

devcontainer.wrap_lsp_cmd({cmd} [, {workspace}]) *devcontainer.wrap_lsp_cmd()*
  Wrap an LSP command array for execution inside a Dev Container.

  When a Dev Container is detected in the workspace, this function wraps
  the command with `devcontainer exec`. If no Dev Container is found,
  the original command is returned unchanged.

  Parameters:
  - {cmd} (table): Array of command arguments (e.g., {'gopls'})
  - {workspace} (string, optional): Workspace path (defaults to current directory)

  Returns:
  - (table): Wrapped command array or original command if no Dev Container

  Examples:
  >
    local devcontainer = require('devcontainer')

    -- Single argument
    local wrapped = devcontainer.wrap_lsp_cmd({'gopls'})
    -- Result: {'devcontainer', 'exec', '--workspace-folder', '/path', 'gopls'}

    -- Multiple arguments
    local wrapped = devcontainer.wrap_lsp_cmd({'typescript-language-server', '--stdio'})
    -- Result: {'devcontainer', 'exec', '--workspace-folder', '/path', 'typescript-language-server', '--stdio'}

    -- No Dev Container
    local wrapped = devcontainer.wrap_lsp_cmd({'gopls'}, '/other/project')
    -- Result: {'gopls'} (unchanged)
  <

devcontainer.wrap_for_lsp({config} [, {workspace}]) *devcontainer.wrap_for_lsp()*
  Wrap an entire LSP configuration table by wrapping its cmd field.

  This is a convenience function for wrapping an entire LSP config
  while preserving other fields.

  Parameters:
  - {config} (table): LSP configuration table with cmd field
  - {workspace} (string, optional): Workspace path (defaults to current directory)

  Returns:
  - (table): New config table with wrapped cmd, or original config if no cmd

  Example:
  >
    local devcontainer = require('devcontainer')

    local config = devcontainer.wrap_for_lsp({
      cmd = {'typescript-language-server', '--stdio'},
      name = 'tsserver',
      root_markers = {'package.json'},
    })
    -- Result: {
    --   cmd = {'devcontainer', 'exec', '--workspace-folder', '/path', 'typescript-language-server', '--stdio'},
    --   name = 'tsserver',
    --   root_markers = {'package.json'},
    -- }
  <

Module: devcontainer.cli                              *devcontainer-cli*
  Internal module providing low-level Dev Container CLI operations.

  devcontainer.cli.up()                            *devcontainer.cli.up()*
    Start the Dev Container for the current workspace.
    Returns: true on success, false on failure.

  devcontainer.cli.exec({cmd})                  *devcontainer.cli.exec()*
    Wrap a command array with `devcontainer exec`.
    Parameters:
    - {cmd} (table): Array of command arguments
    Returns: Array of wrapped command arguments or nil on failure.

    Example:
    >
      local wrapped = require('devcontainer.cli').exec({'gopls'})
      -- Result: {'devcontainer', 'exec', '--workspace-folder', '/path/to/workspace', 'gopls'}
    <

Module: devcontainer.detection                    *devcontainer-detection*
  Internal module for Dev Container detection.

  devcontainer.detection.has_devcontainer([{workspace}]) *devcontainer.detection.has_devcontainer()*
    Check if a Dev Container configuration exists in the workspace.
    Parameters:
    - {workspace} (string, optional): Workspace path (defaults to current directory)
    Returns: (bool, string) - true and path if found, false and nil otherwise

  devcontainer.detection.find_init_file([{workspace}]) *devcontainer.detection.find_init_file()*
    Find `.devcontainer/init.lua` or `.devcontainer/init.vim` in the workspace.
    
    Searches for init files in this order:
    1. `.devcontainer/init.lua` (takes precedence)
    2. `.devcontainer/init.vim`
    
    Parameters:
    - {workspace} (string, optional): Workspace path (defaults to current directory)
    Returns: (string) - Path to init file if found, nil otherwise

TROUBLESHOOTING                                  *devcontainer-troubleshooting*

Dev Container CLI not found~
  Ensure the Dev Container CLI is installed and accessible in your PATH.
  Install it from: https://github.com/devcontainers/cli

No .devcontainer configuration found~
  Add a `.devcontainer/devcontainer.json` or `.devcontainer.json` file
  to your project root. Refer to the Dev Container specification:
  https://containers.dev/

Debug logging~
  Enable debug logging to see detailed information:
  >
    require('devcontainer').setup({ log_level = 'debug' })
  <
